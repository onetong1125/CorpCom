# Working Memory 与 Long-term Memory

本文记录 CorpCom 已确认的跨会话记忆设计。当前已有 Thread checkpoint、运行历史、工作区研究档案和资料库。工作笔记已接入 Agent 和工作台的「记忆」面板，两级长期记忆已支持存储层的创建、修订、忘记和面板只读预览，Agent 已在每轮开始时加载两个作用域的索引，长索引的预算截取及按需读写工具待接入。[现有存储](workspace-local.md)

| | Working Memory · 工作笔记 | Long-term Memory · 长期记忆 |
| --- | --- | --- |
| 回答的问题 | 这个工作区做到哪里了，下一步接什么？ | 以后做相关研究时，哪些判断、经验或约定值得沿用，依据是什么？ |
| 怎么组织 | 每个 Workspace 根目录一份 Markdown 文件 `agent.md`，同一工作区的 Thread 共用。 | 用户级和 Workspace 级各有目录。每个目录用 `memory.md` 索引同目录下的主题 Markdown 文件。 |
| 怎么写 | 实质进展发生时，Agent 主动更新对应任务。用户说“下一步先做这个”也可以更新。 | 按内容类型决定触发条件和作用域。Agent 读取已有主题后新增、修订或撤回；用户可以明确要求记住、纠正或忘记。 |
| 怎么查看 | 用户可以直接打开或编辑 `agent.md`，也可以在「记忆 → 工作笔记」预览同一份文件。Agent 每轮从文件读取最新内容。 | Agent 每轮看到两个作用域的简短目录，按题读取详情。用户在「记忆 → 长期记忆」切换「当前工作区」「我的全局记忆」，展开主题查看正文和依据，也可以在本地编辑器里打开同一文件。 |

### 工作台中的记忆面板

用浏览器打开[交互原型](prototypes/corpcom-memory-panel.html)，可切换工作笔记、两个长期记忆范围和资料库。

在研究空间标题下的「研究档案」旁增加「记忆」按钮。点击后，工作台右侧资料库的位置切换为记忆面板，当前会话和输入草稿继续保留；关闭后返回原资料库视图。窄屏进入单栏面板，关闭后回到原会话。首版采用只读预览，用户在本地编辑器修改 Markdown。

- **工作笔记**是首次打开时的默认页，展示当前 Workspace 的 `agent.md` 文件名和完整 Markdown 预览。已有工作区尚无笔记内容时显示空笔记状态。
- **长期记忆**先展示「当前工作区」，可以切换到「我的全局记忆」。两个作用域各自列出主题，点标题展开文件名、正文及文件中记录的依据。主题为空时显示该作用域的空状态。
- 每次打开面板或切换范围时重读对应文件。读取失败时保留当前范围并提供重试入口，缺失的主题文件显示对应文件名，便于用户核对索引。

## 1. Working Memory：接手当前工作

**文件位置。** 工作笔记采用 UTF-8 Markdown。默认数据目录下的路径为 `data/workspaces/<workspace_id>/agent.md`，与 `research.json` 同级。用户可以直接用文本编辑器打开。新工作区创建时写入初始模板；已有工作区首次使用工作笔记时补建缺失的文件。初始化只创建缺失文件，保留用户已经写好的内容。

**笔记内容。** 下面是一份示例。进行中的事项放在开头，会话和产物只记便于追查的指针，详细过程沿用已有历史和资料库。

```markdown
# 工作笔记

## 当前进展与下一步
- [ ] 年报已核对。下一步用季报核实经营现金流改善是否来自回款时点。

## 会话与关键发现
- 年报核查（Thread A）：全年现金流改善，原因待核实。

## 资料与产物
- [年报对账底稿](tasks/年报核查/对账.md)
```

**怎么写。** 形成实质进展时，Agent 先读当前文件，用现有 `edit_file` 修改对应段落。例如 B 核实季报后，将上述待办勾为完成并补一句依据。若旧文本已被用户或其他会话修改导致匹配失败，重新读取并合并。只记已经确认的进展，未完成事项写成待办。[文件工具](../src/corpcom/workspace_file_tools.py)

**怎么看。** 每轮开始时，后端从当前 Workspace 的 `agent.md` 读最新文本；用户在编辑器保存的下一步也能出现在下一轮模型输入中。笔记过长时，只在模型输入中按预算截取并提示可按需读取原文件。页面「记忆 → 工作笔记」按当前 Workspace 读取和渲染完整 Markdown。文件正文是模型和页面共同的来源。

## 2. Long-term Memory：沉淀可复用内容

**目录与配置。** 长期记忆以宿主机上的 UTF-8 Markdown 文件为准。以下路径相对于服务实际使用的数据目录（默认 `data/`，可通过 `CORPCOM_DATA_DIR` 指定）。

```text
user/memory/                         # 所有 Workspace 共用
  memory.md                          # 主题链接和一句话说明
  feedback_report_style.md
workspaces/<workspace_id>/
  agent.md                           # 本工作区的工作笔记
  memory/                            # 本工作区的长期记忆
    memory.md
    project_cashflow.md
```

用户级目录通过后端环境变量 `CORPCOM_USER_MEMORY_DIR` 配置，可在 `.env` 中设置，例如 `CORPCOM_USER_MEMORY_DIR=~/.corpcom/memory`。未设置时使用数据目录下的 `user/memory/`。绝对路径直接使用，相对路径以数据目录为基准。后端启动时解析一次，工具、提示词加载和页面接口使用同一目录。修改配置并重启后，所有 Workspace 都读取新目录中的文件；如需沿用旧内容，部署者将旧目录移到新位置。工作区级记忆始终位于对应工作区的 `memory/`。用户级目录应独立于工作区挂载目录，配置解析时检查两者是否重叠，以维持作用域隔离。

**主题与索引。** 每个主题文件的 frontmatter 包含 `name`、`description`、`type`，正文记录可复用内容、适用条件和来源。索引每行写一个相对链接和一句话，例如 `- [经营现金流](project_cashflow.md) — 年报与季报对回款时点的解释`。主题通过作用域和文件名定位。修订研究判断时沿用原文件，在正文中注明改变的原因、日期和证据出处。

| 类型 | 作用域和写入条件 | 例子 |
| --- | --- | --- |
| 用户信息（user） | 用户级。只记录用户主动明确、可跨项目使用的信息。 | “我通常关注三到五年的经营趋势。” |
| 反馈（feedback） | “以后所有报告……”进入用户级；明确针对当前项目的约束只在该 Workspace 生效。已有研究档案偏好字段承载的值继续由档案管理，项目设置优先于通用默认。 | “以后财报比较都注明单位”；“这个项目的报告要简短”。 |
| 研究主题（project） | Workspace 级。形成有证据且会影响后续研究的判断、方法或决策时主动保存。 | “分析现金流改善时要拆开回款时点与持续经营能力”，附年报页码和季报表名。 |
| 参考资料（reference） | 项目资料进入 Workspace 级；用户明确指定通用的公开来源或核查方法可进入用户级。 | 本项目的年报对账底稿；用户要求各项目优先查阅的公开披露平台。 |

**后端工具如何跨 Workspace。** 模型传入 `scope`（`user` 或 `workspace`）和主题文件名。后端的 `read_memory`、`write_memory` 在宿主机执行：用户级请求解析到配置的共享目录；工作区级请求解析到当前会话绑定的工作区目录。文件名限定为所选目录内的 Markdown 文件，路径解析须防止绝对路径、目录穿越和符号链接越界。沙箱继续只挂载当前工作区。[现有后端工具入口](../src/corpcom/workspace_tools.py)

**写入与纠正。** Agent 先查看索引，已有主题先读原文再合并，新主题写入详情并在 `memory.md` 中添加链接。后端负责完成这两步后报告成功；重试时按同一文件名补齐索引，避免重复条目。忘记主题时移除索引引用并删除对应主题文件。用户可直接编辑 Markdown；更新已有主题前检查读取后的文件是否已被改动，冲突时重读合并。用户级内容只保存跨项目通用的信息，项目证据保存在所属 Workspace。

**模型和用户怎样查看。** 每轮从磁盘读取用户级和当前工作区的两份 `memory.md`，在输入预算内注入索引。比如模型从当前项目索引看到现金流条目，调用 `read_memory(scope="workspace", key="project_cashflow.md")` 读取当前判断和依据。目录过长时可在同一作用域中继续查找。页面「长期记忆」按作用域列举并读取相同文件。用户用本地编辑器修改正文后，下次读取应看到最新内容；手工新增主题时，在对应索引补一行即可让 Agent 从目录发现它。

## 3. 两类记忆如何配合

以财报核查为例，以下是验收用的模拟数据：

1. 会话 A 读完年报。工作笔记更新为“年报已核对，待用季报拆解回款时点”，附产物入口。此时只有待验证的问题。
2. 会话 B 从工作笔记接手，读完季报。工作笔记把核查任务标为完成；长期记忆在项目层新增现金流主题，记录判断、报告期和两份材料中的依据。用户同轮说“今后所有项目的金额都注明单位”，另存一条用户级反馈。
3. 在原 Workspace 新建会话 C。“接下来查什么”先查工作笔记，“为什么这么判断”查长期主题和证据。切换到另一个 Workspace 后，仍可采用金额单位偏好，现金流主题和年报链接仅在原项目可见。

**写入生效时间。** 文件工具完成写入即生效。后续研究若中断，已保存的笔记和长期主题仍可查看，因此写入时区分已有证据与待核实事项。

## 4. 实施顺序与验收

| 阶段 | 最低验收 | 协作估算 |
| --- | --- | --- |
| 工作笔记的组织、写入和读取 | A 写下进展，用户直接编辑文件里的下一步，B 首问能看到修改；B 勾选完成后刷新页面，预览与磁盘原文一致。另一 Workspace 只读自己的笔记。 | 3–5 小时 |
| 两级长期记忆及修订 | 分别验默认路径和自定义路径：A 保存用户偏好，B 可读取，编辑器改动后页面和 Agent 都读到新正文；A 的项目判断仅 A 可读。切换用户目录并重启后，B 使用新目录，A 的项目主题仍在原处。修订和忘记后核对索引与文件。 | 5–8 小时 |
| Agent 的读写路径 | 检查新 Thread 实际收到的工作笔记和两个作用域目录，提问后能读取相关详情。重复、失败、中断和并发场景按上述规则处理。 | 4–7 小时 |
| 页面查看与验收 | 用户能分别打开工作笔记、项目和用户级长期记忆。完整跑通 A → B → C，核对来源、隔离和重启恢复。 | 3–5 小时 |

合计预估 15–25 小时。开发者负责后端功能；助手负责测试、前端和文档。先验工作笔记的跨 Thread 接手，再接长期主题。保留用户级记忆意味着必须额外验证跨项目可见内容；主题修订意味着页面要能展示判断变化的理由，这两项已计入估算。
