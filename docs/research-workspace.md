# CorpCom 首个持续研究案例与最小设计

状态：2026-10-06 用户确认研究案例与报告约定；截至 2026-10-10，Workspace 基础存储、多会话消息、文件导入及模型对话入口已实现，并通过 [后端 HTTP 接口](backend-api.md) 暴露给前端调用；存储结构与自动验收见 [本地存储说明](workspace-local.md)。报告生成、新闻与定时任务尚未实现。

## 1. 已确认的首个演示案例

Workspace 围绕研究目标组织内容。研究目标可以是单家公司跟踪、多家公司比较、行业观察或某个事件对投资假设的影响；分析对象的数量和指标由具体问题决定。以下双公司案例用于首批数据与流程验收，不限定通用报告结构。当前已验证的数据能力仍限于上述接口实测范围，其他目标需要按实际数据与工具覆盖情况说明能力缺口。

| 项目 | 内容 |
| --- | --- |
| 研究对象 | 贵州茅台（600519）、五粮液（000858） |
| 初始假设 | 贵州茅台的经营韧性更强；这是待验证判断，不预设结论 |
| 观察周期 | 创建研究后未来三个月；实际开始、结束日期在创建时保存 |
| 核心证据 | 营业收入、归母净利润、经营活动产生的现金流量净额及同比变化 |
| 更新方式 | 每日检查新闻与行情；财报发布后更新经营分析 |
| 首份交付物 | 初始研究报告，列出支持证据、反对证据和待验证问题 |

“经营韧性”第一版用收入与利润增长的持续性、经营现金流变化来讨论，不做单一加权分数。比较同一报告期的同比与多期变化，金额规模差异不直接等于韧性差异。现金流明显恶化、增长优势反转等应列入反对证据；没有新证据时不强行调整判断。股价是补充观察，不用股价涨跌直接证明经营假设。

尚未给出的风险偏好、实际仓位和交易记录保持未填写。Agent 不把三个月的观察周期推断成用户的实际持有期限，也不凭空生成持仓建议。

## 2. 演示的四段流程

1. 创建 Workspace，确认目标、假设和关注指标；获取数据，生成初始报告，保存来源、数据、代码和图表。
2. 关闭再打开应用，在同一 Workspace 新建 thread；Agent 读取研究目标、偏好、最新假设及已有报告，回答一个后续问题，并引用此前产物。
3. 获取新财报或新闻，对比上次证据，生成更新报告和假设修订记录。新报告关联旧报告，旧文件仍可查看。
4. 用户配置每日更新时间与时区；到期使用同一研究流程执行，Workspace 内显示执行状态与更新报告。失败记录原因，不伪装成“无变化”。

实际研究使用当时已公开的最新可用数据。接口验收固定使用 2023、2024 年年度值，便于对账，不把这两年称作当前最新数据。

现场如需历史回放，必须标明“历史回放”及研究截止时间。按原始公告/新闻发布时间控制可见证据，保留数据版本；今天接口返回的历史值可能经过重述，不能据此宣称已还原历史可见数据。首次披露时间和版本未核验前，仅演示文件承接与更新机制，不宣称完成严格历史回放。

## 3. 两种报告的内容约定

报告保留共同的研究记录要求，分析正文由研究目标决定。Agent 根据目标、用户偏好和可获取的证据，明确本次要回答的子问题、所需数据、分析方法与交付形式，并保存到 Workspace；后续会话可继续使用或修订。

### 初始报告

- 研究目标、研究范围与对象、初始假设、观察周期、用户已确认的偏好。
- 研究截止时间、生成时间、实际覆盖的数据期间。
- 围绕研究问题的分析：按目标选择指标、比较基准、时间范围及方法，组织必要的定量计算和定性证据；采用公司间比较、历史趋势或事件分析时，说明选择理由与可比口径。
- 按分析需要提供表格或图表，注明来源、单位和时间范围；涉及行情时注明复权方式。
- 支持证据与反对证据，分别关联数据文件/原始报告/新闻条目。
- 当前判断与理由、资料不足之处、待验证问题和下一次关注事件。
- 来源清单：链接、抓取时间、报告期/新闻发布时间、单位、口径、数据版本。

### 更新报告

- 所承接的报告与假设版本、本次检查区间。
- 新证据及其与旧证据的差异；已存在新闻去重，缺失与无变化分别表述。
- 对假设的影响：增强／不变／减弱，逐项说明证据与理由；这不是校准过的概率。
- 修订后的假设或维持原假设的理由，以及未解决的问题。
- 数据与执行状态：哪些更新成功，哪些失败；来源、代码和文件索引。

模型可提出假设修订，不能默默替换用户的研究目标或偏好。用户明确表达的新偏好才进入持久化偏好；Agent 的推断先作为待确认建议。

### 首个演示案例的具体分析要求

茅台与五粮液案例采用两家公司同期间的营业收入、归母净利润、经营现金流净额及同比，结合历史变化检验“经营韧性”假设。这些是本案例的验收项。单家公司跟踪可围绕自身历史变化展开，事件研究可围绕事件时间线、影响路径和证据展开；实际采用哪些分析，取决于目标与数据可得性。

## 4. 最小 Workspace 设计与实现范围

先做单用户本地版本：SQLite 保存结构化状态，磁盘保存研究文件。数据库和文件放在应用持久数据目录中，独立于 Docker 容器生命周期；不使用容器内存保存长期研究。

| 记录 | 最少保存什么 |
| --- | --- |
| Workspace | ID、标题、目标、研究范围与关注对象（不限定公司或数量）、观察周期、偏好 JSON、创建/更新时间 |
| Thread 与 Message | Workspace ID、thread ID、角色、内容、时间；可追溯偏好或目标修改来自哪条消息 |
| 假设版本 | Workspace ID、假设内容、相对上一版的信心变化、理由、证据文件 ID、创建时间和前一版 ID |
| Run | Workspace/thread ID、手动或定时触发、状态、起止时间、研究截止时间、错误信息、所用偏好与假设版本快照 |
| Artifact | Workspace/run ID、类型、相对路径、来源与时间口径；报告指向所承接的上一份报告 |
| Schedule | Workspace ID、频率、本地时间、时区、启用状态、下次执行时间 |

当前已用表与 JSON 字段实现 Workspace、Thread、Message、Artifact。初始假设暂存于 Workspace 字段，假设版本、Run、Schedule 待后续批次实现。Artifact 当前记录导入文件的类型与路径，来源、Run 关联和报告承接关系随研究执行接入；偏好当前由用户命令显式保存，修改历史与来源消息关联待后续实现。

研究范围以文本保存，研究计划可作为普通文件产物导入；当前无需为公司、行业、事件分别建立专用数据模型。目标相关的指标与分析安排保存在研究计划中，不在 Workspace 结构里固定两个股票代码或三项经营指标。

当前目录（后续执行产物再按 Run 归档）：

```text
data/
  corpcom.db
  workspaces/<workspace_id>/
    files/<artifact_id>/<原文件名>
```

同一 Workspace 的所有 thread 共享研究目标、偏好和产物索引，当前可通过命令读取。模型对话入口向新 thread 提供这些状态与索引，并允许按需读取旧会话及文本文件，不把全部旧对话无差别塞入模型。事实和结论须可回溯文件来源。跨 Workspace 不自动混用偏好或文件。

Docker 执行时计划把本次输入作为只读挂载、输出作为可写挂载。模型只收到结果摘要和产物索引，完整数据留在文件系统。当前 `run_python` 只有单次运行目录挂载，下一批根据实际需要调整。

先限制同一个 Workspace 同时只有一个研究运行，避免报告相互覆盖。Run 的最小状态为 queued/running/succeeded/failed；应用重启后把中断的 running 标记失败并保留文件。调度器复用同一研究入口；本地应用需保持运行，到期未运行应明确显示错过，恢复后最多补一次更新，不补跑全部历史时点。时间和时区由用户在启用时确认；本批不启用真实定时任务。

## 5. 后续实现顺序与验收

1. **Workspace 持久化与多会话（已实现）**：创建研究，保存目标/偏好/初始假设，跨进程重新读取同一研究及已有文件并新建 thread；不同 Workspace 的会话和文件通过所属 ID 检查隔离。Agent 已能读取这些状态和资料继续对话，工具定义与执行循环已迁移至 LangChain。
2. **第一份研究报告**：按研究计划组织分析，用已接入的经营数据工具与 Docker PTC 完成已确认的双公司案例，验证计算和来源可复核、报告/数据/代码可查看。从本阶段开始积累可复跑的评测案例与实际结果，检查数值计算、来源追溯、跨会话读取和执行失败处理，并记录模型实际返回的用量及执行时间。
3. **增量研究与前端**：再次运行能引用上一份报告、识别新证据、保留版本，在界面展示过程和产物。
4. **新闻与调度**：先验证新闻来源、时间与去重，再启用定时任务；到期确实执行、失败可见、重启后配置仍存在。
5. **多 Agent 与交付整理**：按已存在的研究分工拆任务，使用此前积累的评测案例比较拆分前后的结果正确性、执行时间和模型用量；最后完成演示及简历材料。

评测贯穿上述阶段：增量研究接入后增加新旧证据比较与报告承接检查，新闻与调度接入后增加去重、到期执行和失败可见性检查。简历中的能力与效果以实际完成的功能和保存的验收记录为依据。

## 6. 本批验收

- 首个演示案例的两家公司 2023/2024 同期间三项指标可真实获取，金额单位、合并口径和字段含义经过核对。
- 保存可复跑探针与实际结果；指出公告时间/修订版本限制。
- 初始报告和更新报告各自回答什么、Workspace 如何承接新会话，已明确。
- 新闻接口、定时调度、首次披露版本还未验证，不列入“已跑通”。具体接口证据见 [资料核查](financial-data-sources.md) 和 [实测记录](financial-data-validation.md)。
