# 经营数据接口实测记录

## 结论

2026-10-06 在本机 Python 3.11 / AKShare 1.19.1 下，真实调用 `stock_financial_report_sina` 获取贵州茅台、五粮液的利润表和现金流量表成功。

两家公司 × 两个年度（2023、2024）× 三项指标，共 **12 个金额与 2024 年原始年报中的本期及比较数一致，按人民币元保留两位小数对账通过**；自行计算的 6 个同比保留两位小数后，与年报披露百分数一致。原始年报链接及精确金额见 [资料核查](financial-data-sources.md#原始年报对账基准)。

本批验证的是接口和固定样本的数据语义，未生成投资研究结论，也未验证每日稳定性、所有上市公司或历史首次披露版本。

## 接口与字段

```python
ak.stock_financial_report_sina(stock="sh600519", symbol="利润表")
ak.stock_financial_report_sina(stock="sh600519", symbol="现金流量表")
# 五粮液使用 stock="sz000858"
```

| 目标 | 报表与字段 | 本次核对口径 |
| --- | --- | --- |
| 营业收入 | 利润表 → 营业收入 | 合并、人民币元、全年累计 |
| 归母净利润 | 利润表 → 归属于母公司所有者的净利润 | 合并、人民币元、全年累计 |
| 经营现金流 | 现金流量表 → 经营活动产生的现金流量净额 | 合并、人民币元、全年累计 |
| 报告期 | 报告日 | 20231231 / 20241231，不是公告日期 |
| 币种与范围 | 币种、类型 | 实测为 CNY、合并期末 |

同比由本期金额和上年同期金额计算：`(本期 / 上年同期 - 1) × 100%`。本样本的上年基数均为正。以后接入季度、负基数或零基数时，需要单独定义展示口径；本脚本不代替生产财务工具。

## 如何在本地复跑

在项目根目录执行：

```bash
uv run python examples/probe_fundamentals.py
```

脚本固定验证本案例，发起四次报表请求，检查报告期、币种、合并范围和金额是否有效，计算同比，保存结果并打印目录。没有模型调用，不需要读取 `.env`，不需要 Docker。

本次真实输出：`runs/fundamentals-20261006T102611486758Z/`，包含：

- 两家公司各一份利润表、现金流量表 JSON，共四份。这是 AKShare 返回表的直接序列化，**不是未经解析的 HTTP 原文**。
- `summary.json`：选出的年度金额、同比、AKShare 版本、抓取时间、来源链接和上游日期原值。金额用字符串保存到分。

`runs/` 已被 Git 忽略；其他机器复跑会创建新的带时间戳目录。金额与原始年报的对账由本批独立检查完成，探针自身不会下载年报进行自动对账。脚本用 90 秒进程时限约束无 timeout 参数的 AKShare 请求，适用于当前 macOS/Linux 环境；请求失败或超时直接失败，部分已下载文件会保留。

## 已发现的限制

1. 同花顺 `stock_financial_abstract_new_ths` 和新浪 `stock_financial_abstract` 本次都能获取两家公司摘要，但其中“营业总收入”不能映射成“营业收入”。茅台 2024 年两者相差约 32.45 亿元；正式字段优先取新浪三大报表。
2. 新浪返回的茅台 2024 年行 `公告日期=20260417`，五粮液对应行 `公告日期=20260430`，而更新日期分别在 2025-04-02 和 2025-04-25。这些上游字段不能证明首次披露时间。探针保留原值，并明确 `first_publication_verified=false`，不擅自修正日期或推断原因。
3. 当前接口可能返回经过后续更新的历史数值。要演示严格历史回放，还需验证原始公告时间和数据版本；对历史年度获取成功不等于完成了该验证。
4. 本次只验证宿主机数据链路。经营数据尚未加入 Docker 工具、Agent 提示词或生产报告；新闻接口、定时任务也未验证。
5. 首次受限执行环境因 DNS 失败而未能访问；允许外部网络后的实际请求成功。这是执行环境限制，不构成接口字段不可用的证据。普通本地终端仍需要能访问新浪财经。
