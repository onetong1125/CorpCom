# 提示词与上下文管理阶段计划

本计划细化[开发路线](roadmap.md)中的“提示词与上下文管理”。四个阶段均已完成验收。

## 预估工时

按双方实际推进任务的时间估算。后端每次推进一个小改动，开发者负责功能实现，助手负责编写、维护和运行测试。动手前，助手说明测试场景和预期行为；开发者回复 `done` 后，助手检查 diff，报告哪些断言通过或失败以及原因。估算包含讨论、验证和小幅返修；两次协作之间的等待时间另计。

| 阶段 | 预估工时 | 主要耗时 |
| --- | ---: | --- |
| 1. 提示词模板化 | 1–2 小时 | 迁移正文和条件分支，对照空档案与已有档案的渲染结果。 |
| 2. 默认配置与每轮研究信息 | 1–2 小时 | 接入 YAML 默认值，复用现有档案读取逻辑，检查同会话追问和新会话首问的实际输入。 |
| 3. 长对话与大工具结果 | 4–7 小时 | 商定计数和缩减策略，接入模型调用，验证长结果、并行调用和裁剪边界。策略尚待确定，这一阶段的估算浮动最大。 |
| 4. 追问与刷新恢复验收 | 2–3 小时 | 构造含工具错误和半截输出的会话，触发压缩后追问，再从历史接口和页面核对原始记录。按复用现有恢复流程估算。 |
| **合计** | **8–14 小时** | 四阶段依次推进至最低验收通过。 |

## 1. 把现有系统提示词迁到模板

**目标**　研究规则和工具说明可以直接在文本模板里阅读和修改。

**工作**　保留现有 `build_workspace_prompt()` 调用入口，先把正文迁到一个 Jinja2 模板。Python 准备工作区资料、初始化条件和沙箱数据函数简表，模板负责排版与条件段落。参考 LangAlpha 的 `prompts/templates/system.md.j2` 和 `prompts/loader.py`。[现有提示词](../src/corpcom/workspace_prompt.py)

**最低验收**　取一份空研究档案和一份已有研究目标的档案，分别对照迁移前后的渲染结果。前者在工作区首问时包含初始化指令，后者包含按用户要求更新的指令。两份提示词中的工具使用规则、函数简表、研究字段值与原先一致。

## 2. 组合默认配置和每轮研究信息

**目标**　已有工作区可以连续使用，新一轮模型调用能看到用户刚保存的研究目标和偏好。

**工作**　用 YAML 管理模板实际使用的默认配置。每轮创建 Agent 时，从当前 Workspace 读取研究档案和其他会话索引，将这些值传给模板。研究档案继续以 `research.json` 为准。这里参考 LangAlpha 的 `prompts/config/prompts.yaml` 和渲染时传入运行参数的做法。[Agent 组装入口](../src/corpcom/workspace_agent.py) · [工作区数据来源](workspace-local.md)

**最低验收**　修改一项模板默认配置，用相同输入重新渲染，能观察到对应变化。在同一 Thread 首问后，把目标从“检查营收”改为“检查经营现金流”，下一轮实际模型请求的系统消息包含新目标和已有偏好。另开同一 Workspace 的 Thread，也能看到新目标和旧会话索引。模型输入可用现有 `ScriptedModel.requests` 核对。[模型请求测试](../tests/test_workspace_agent.py)

## 3. 让长对话和大工具结果仍能继续使用

**目标**　历史累积或单个工具返回大量文本后，Agent 仍能收到当前问题和可用证据，在模型输入额度内继续回答。

**工作**　在模型调用处计算本次输入，覆盖系统提示词、绑定的工具声明、历史消息及工具结果，并为回答留出空间。短会话直接使用完整输入。超限时，缩减旧历史或过长的工具内容；保留的每个工具调用都能按 ID 找到结果，失败结果也参与配对。参考 LangAlpha 的 `middleware/compaction/middleware.py`，处理本次请求时保留原始历史供回看。

**最低验收**

- 短会话在预算内。对照处理前后的实际模型输入，消息内容、顺序和工具结果一致。
- 准备多轮历史，最后一问明确引用最近一轮得到的数值。用较小的测试额度触发压缩，核对实际请求在约定的计数口径内，且模型仍能看到本轮问题和该数值。
- 同轮并行调用两个工具，一个返回长文本，一个返回错误。在工具执行后的下一次模型请求中，两个 ID 各有一条结果，能识别可用信息及失败原因。到后续轮次，这组旧消息遇到裁剪边界时，保留下来的调用和结果仍能完整配对。

**已验收**　使用 LangChain 的近似计数，超限时先移除最早的完整轮次，再按需缩短当前轮中成功工具返回的文本。测试检查了模型实际收到的消息和 checkpoint 中的完整原文。生产阈值仍需用真实请求校准。[工作区 Agent 回归](../tests/test_workspace_agent.py) · [预算配置](backend-api.md#服务配置)

## 4. 验收压缩后的追问与刷新恢复

**目标**　同一份研究既能在精简上下文中继续，也能从页面查回实际发生的过程。

**工作**　使用同一 Thread 做两次观察。先看追问时模型收到哪些消息，再刷新并从侧栏重新打开该 Thread，核对历史接口与页面展示。[历史接口](backend-api.md) · [历史恢复回归](../tests/test_run_history.py)

**最低验收**　在该 Thread 中记录一次带文字计划的工具调用、一个成功结果、一个工具错误，以及一次失败或中断前的半截输出。随后触发上下文压缩并追问，确认模型收到精简输入并完成本轮回答。重新打开会话后，能按原轮次展开工具，看到原先记录的结果与错误，读到当时的计划和半截输出。用压缩前记录的内容逐项对照。
