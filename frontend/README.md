# CorpCom 本地前端

Vue 3 + Vite 单页研究工作台，连接仓库现有 FastAPI 接口。模型配置和密钥只留在后端。

## 启动

需要 Node.js 22.12+（本次验证为 Node 26.3.1）和 npm。

在仓库根目录启动后端；已有服务时不重复启动：

```bash
docker compose up -d redis
.venv/bin/python -m uvicorn corpcom.api:create_app --factory --host 127.0.0.1 --port 8001
```

后端 `.env` 需配置 `CORPCOM_REDIS_URL`，示例地址为 `redis://127.0.0.1:6380/0`。修改 Python 后重启后端，或开发时加 `--reload`；新路由返回 404 时先核对运行中服务是否已加载代码。

另开终端：

```bash
cd frontend
npm ci
npm run dev
```

打开 http://127.0.0.1:5174 。`/api` 通过开发服务器代理到 `http://127.0.0.1:8001`，不依赖浏览器跨域设置。固定端口避免误连本机其他项目；端口被占用时直接报错。

其他后端地址通过启动环境变量配置，也可以写入不入库的 `frontend/.env.local`：

```bash
CORPCOM_API_URL=http://127.0.0.1:8000 npm run dev
```

这是开发服务器配置，不是前端模型密钥。不要将任何模型密钥放进 `VITE_*` 变量。

## 当前功能

- 创建、搜索和选择研究空间；查看研究档案；编辑完整偏好 JSON。
- 创建会话、恢复历史、发送研究问题。URL 保留所选研究和会话，刷新后恢复。
- 按 Thread 展示研究中、已完成、失败和中断状态；仅运行中的会话禁止重复发送。可以切换或新建会话并发研究，整体最多同时运行两轮，满额由后端拒绝。使用按钮或 Cmd/Ctrl + Enter 发送；Enter 换行。
- 发送时固定 Workspace／Thread，回答和错误不会串到后来选择的会话。草稿在页面内按 Thread 保留，成功后清空对应草稿；失败保留输入但不自动重发，再次发送会新增请求。
- 当前 Workspace 有运行中的会话时，每次读取完成后间隔 2 秒刷新消息、状态和产物；切换后只更新当前 Workspace，离开的 Workspace 在重新进入时读取。过期读取结果不会覆盖新的页面选择。
- 上传状态和错误按 Workspace 保存，研究中可以上传，上传中也可以切换会话或开始研究。
- 产物按归档目录分组，保留 v1/v2；Markdown 报告预览，文本/代码预览，文件下载和资料上传。
- Markdown 渲染经过 DOMPurify 清理。窄屏使用折叠导航，产物位于对话下方。

消息发送使用 POST `/messages/stream`，通过 Fetch 读取 SSE。文本按模型消息 ID 累积；工具事件区分回调执行 ID 与模型调用 ID。完整操作计划生成后保存，最终回答与成功状态一起保存。页面按 `model_message_id` 避免已保存消息与流式文本重复，研究过程放在对应轮次中，支持展开调用参数和工具结果。

页面内切换会话继续接收原会话事件；关闭页面只关闭连接，不取消后台研究。断连且已收到 Run ID 时，使用 GET `/runs/{rid}/events?after=<cursor>` 重连，成功应用事件后才推进游标，不重复 POST 问题。未收到 Run ID 时查询已有消息与状态，不自动重发。原有的每 2 秒刷新仍用于消息、运行状态和产物同步，不代替 Redis 事件重连。

整页刷新或首次切换到某个会话时：

- 运行中的 Run 从 Redis `0-0` 重建事件并继续接收。
- 已结束的 Run 请求 `/runs/{rid}/history`，显示 checkpoint 的消息和工具结果，并补入事件归档中的缺失尾部输出；归档不存在时后端读取 Redis。
- 没有 Run 关联的旧问题请求 Thread `/history`，按用户消息 ID 分组恢复 checkpoint；同时存在新 Run 的会话也会保留旧问题的历史。

完整的 `assistant_message` 替换对应文本，不能当作 `text_delta` 再追加；工具用 `tool_call_id` 关联。缺少模型消息 ID 的旧业务回答，仅在同一问题范围内按完全相同的文本关联，避免重复显示。没有工具结果时展示“结果未收到”，不推测成功。历史加载错误会显示；旧轮次不会沿用最新轮次的完成状态。

草稿只在当前页面内保留，不跨刷新保存。409、503 和网络错误不会触发自动重新提问；用户再次发送会开始新请求。后端重启会标记中断，不自动续跑。历史数据来源和恢复边界见 [后端接口文档](../docs/backend-api.md#流式执行重连与历史)。目录名用于展示，不代表正式版本关系。

## 历史恢复验收

使用已经存在工具调用的会话，不必重新发起研究：

1. 确认后端已重启并加载 Thread `/history` 路由。
2. 刷新一个没有 Run 记录的旧会话，展开“查看本轮研究过程”，检查工具参数、结果和错误。
3. 从侧栏首次进入另一个旧会话，确认也能显示历史；切回后不重复工具卡片或回答。
4. 对有 Run 的已结束会话检查 `/runs/{rid}/history`；对运行中会话检查 Redis SSE，恢复操作不应发送新的消息 POST。

`tests/serve_backend.py` 是较早的临时 UI 验收脚本：它不调用真实模型或 Docker，但事件格式尚未补齐当前的 `tool_call_id` 和结果字段，也不写 Agent checkpoint，因此暂不能用于新版历史回放验收。它使用临时 SQLite 和文件目录，但 Redis 沿用后端环境配置，不应将其视为所有存储都隔离的测试。脚本适配另行处理。
