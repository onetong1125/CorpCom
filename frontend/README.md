# CorpCom 本地前端

Vue 3 + Vite 单页研究工作台，连接仓库现有 FastAPI 接口。模型配置和密钥只留在后端。

## 启动

需要 Node.js 22.12+（本次验证为 Node 26.3.1）和 npm。

在仓库根目录启动后端；已有服务时不重复启动：

```bash
.venv/bin/python -m uvicorn corpcom.api:create_app --factory --host 127.0.0.1 --port 8001
```

另开终端：

```bash
cd frontend
npm ci
npm run dev
```

打开 http://127.0.0.1:5174 。`/api` 通过开发服务器代理到 `http://127.0.0.1:8001`，不依赖浏览器跨域设置。固定端口避免误连本机其他项目；端口被占用时直接报错。

其他后端地址通过启动环境变量配置，也可以写入不入库的 `frontend/.env.local`：

```bash
CORPCOM_API_URL=http://127.0.0.1:8000 npm run dev
```

这是开发服务器配置，不是前端模型密钥。不要将任何模型密钥放进 `VITE_*` 变量。

## 当前功能

- 创建、搜索和选择研究空间；查看研究档案；编辑完整偏好 JSON。
- 创建会话、恢复历史、发送研究问题。URL 保留所选研究和会话，刷新后恢复。
- 按 Thread 展示研究中、已完成、失败和中断状态；仅运行中的会话禁止重复发送。可以切换或新建会话并发研究，整体最多同时运行两轮，满额由后端拒绝。使用按钮或 Cmd/Ctrl + Enter 发送；Enter 换行。
- 发送时固定 Workspace／Thread，回答和错误不会串到后来选择的会话。草稿在页面内按 Thread 保留，成功后清空对应草稿；失败保留输入但不自动重发，再次发送会新增请求。
- 当前 Workspace 有运行中的会话时，每次读取完成后间隔 2 秒刷新消息、状态和产物；切换后只更新当前 Workspace，离开的 Workspace 在重新进入时读取。过期读取结果不会覆盖新的页面选择。
- 上传状态和错误按 Workspace 保存，研究中可以上传，上传中也可以切换会话或开始研究。
- 产物按归档目录分组，保留 v1/v2；Markdown 报告预览，文本/代码预览，文件下载和资料上传。
- Markdown 渲染经过 DOMPurify 清理。窄屏使用折叠导航，产物位于对话下方。

消息发送使用 `POST /api/workspaces/{workspace_id}/threads/{thread_id}/messages/stream`，通过 Fetch 读取 SSE。文本按模型消息 ID 累积，工具按调用 ID 展示执行中、已返回或执行异常。后端在完整操作计划生成后立即保存，最终回答与成功状态一起保存。前端读回消息后，按 `model_message_id` 移除对应的流式文本，保留其他尚未保存的文本和工具事件；成功后剩余过程折叠展示。后续执行失败时，已完成的计划仍保留在聊天记录中，未完成的文本仅在当前页面展示。

页面内切换会话会继续接收原会话的事件；关闭页面或卸载界面会关闭连接，不取消后台研究。断连后查询后端状态；重新打开或刷新后恢复运行状态、已保存的操作计划和最终回答，不重放工具事件或未完成的文本。草稿只保存在当前页面内，不跨刷新保存。后端重启造成的中断也会显示；409、503 或网络错误不会触发自动重发。目录名用于展示，不代表已实现正式版本关系。

## 隔离的浏览器验收

在仓库根目录执行：

```bash
.venv/bin/python frontend/tests/serve_backend.py
```

另开终端，从 `frontend/` 执行：

```bash
CORPCOM_API_URL=http://127.0.0.1:8012 npm run dev -- --port 5175
```

访问 http://127.0.0.1:5175 ，手动验收：

1. 创建研究空间和会话，发送 `生成 v1`，检查新增报告、数据和代码。
2. 新建会话，发送 `继续查看已有资料`，刷新页面，检查历史恢复。
3. 发送 `生成 v2`，查看两个目录、报告表格，下载两份报告并确认 v1 未变化。
4. 发送 `模拟失败`，检查错误提示、已保存的用户消息和操作计划，以及恢复发送能力；刷新后计划仍在。
5. 修改偏好、上传文件，切换研究空间检查隔离；缩小窗口检查导航和产物面板。
6. 另建一个研究空间及 A、B 两条会话，A 发送 `慢速生成 v1` 后立即切换 B 发送 `慢速查看资料`，确认两条会话同时显示研究中，且能上传文件；`慢速` 请求等待 15 秒，普通请求等待 1 秒。
7. 运行中刷新页面，确认已完成的操作计划仍在、仍显示研究中且不能重复发送；完成后自动显示各自回答，每条会话新增一条用户消息、一条操作计划和一条最终回答。切回 A 查看报告，确认上传文件和报告都在产物列表。
8. 观察刷新前的“研究过程”：工具先显示执行中，返回后显示已返回，回答逐段出现。轮询读到已保存的计划后，计划移入聊天记录，未保存的回答增量继续显示。成功后工具过程折叠，计划和最终回答各显示一次；模拟失败时能看到工具错误。刷新后恢复后端消息与状态，工具过程不重放。

验收后端使用 TemporaryDirectory，退出时清理。HTTP、SQLite 和文件归档使用真实实现，Agent 被确定性脚本替换；不调用模型、Docker 或金融数据接口，不写入真实研究目录。这验证前端交互和接口衔接，不代表真实模型再次完成研究验收。
